# Бизнес-процессы
## 1. Введение
Этот документ описывает ключевые бизнес-процессы, реализуемые в рамках веб-платформы для интерактивного знакомства с методами предиктивного анализа. Цель документа – формализовать последовательность действий, которые выполняют пользователи и система для достижения поставленных целей проекта.

### Основные участники (акторы) процессов:
-  **Пользователь (Гость / Авторизованный пользователь):** Основной актор, использующий платформу для изучения теории и проведения экспериментов с моделями предиктивного анализа. Гость – пользователь, не прошедший авторизацию; Авторизованный пользователь – пользователь, вошедший в личный кабинет.
-  **Система:** Веб-платформа для интерактивного знакомства с методами предиктивного анализа (ML Platform), которая обеспечивает весь функционал: обучение моделей визуализацию результатов, хранение данных пользователя.

## 2. Основные бизнес-процессы
### 2.1. Процесс «Регистрация и вход»
**Цель:** предоставить пользователям возможность создать личный аккаунт и получить доступ к персонализированным функциям платформы (личному кабинету и истории экспериментов).

**БП-1.1: Регистрация нового пользователя**

**Роли:** Гость, Система

1. **Триггер:** 
Гость заходит на платформу и инициирует процесс регистрации.
2. **Шаги:**
   - Пользователь заполняет регистрационную форму (имя, e-mail, пароль).
   - Система проверяет корректность введённых данных (например, уникальность e-mail).
   - Система создаёт учётную запись пользователя в базе данных.
   - Система отображает сообщение: "Проверьте почту для активации аккаунта".
   - Пользователь переходит по ссылке из письма для активации аккаунта.
3. **Результат:** Учетная запись создана со статусом "Неактивен". Пользователь не может войти в систему до активации.
<br><br>

**БП-1.2: Подтверждение и активация аккаунта**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь получает письмо с подтверждением регистрации и переходит по ссылке.
2. **Шаги:**
   - Пользователь открывает письмо с активацией и нажимает на ссылку.
   - Система изменяет статус учетной записи с "Неактивен" на "Активен".
   - Система отображает сообщение: "Аккаунт успешно активирован!"
   - Пользователь автоматически входит в систему или перенаправляется на страницу входа.
3. **Результат:** Учетная запись активирована. Пользователь может войти в систему и использовать все функции приложения.
<br><br>

**БП-1.3: Вход в систему**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь, имеющий учётную запись, открывает форму входа.
2. **Шаги:**
   - Пользователь вводит e-mail и пароль.
   - Система проверяет соответствие введённых данных учётной записи.
   - Система открывает пользователю доступ к личному кабинету.
3. **Результат:** Пользователь авторизован и получает доступ к сохранению и просмотру истории экспериментов.
<br><br>

**БП-1.4: Работа без регистрации (гостевой режим)**

**Роли:** Гость, Система

1. **Триггер:**
Пользователь заходит на платформу и не проходит авторизацию.
2. **Шаги:**
   - Система предоставляет гостю доступ к информационному разделу и обучению моделей.
   - Система не сохраняет результаты экспериментов гостя после завершения сессии.
3. **Результат:** Гость может пользоваться платформой без сохранения истории экспериментов.

### 2.2. Процесс «Изучение теории»
**Цель:** дать пользователю возможность ознакомиться с теоретическими основами методов предиктивного анализа перед практической работой с моделями.

**БП-2.1: Просмотр теоретических материалов по методам**

**Роли:** Пользователь (Гость или Авторизованный пользователь), Система

1. **Триггер:**
Пользователь открывает информационный раздел платформы или переходит в теорию конкретного алгоритма.
2. **Шаги:**
   - Пользователь выбирает интересующий метод (линейная регрессия, логистическая регрессия, случайный лес, k-ближайших соседей).
   - Система отображает описание метода, математическую основу, гиперпараметры, преимущества и недостатки.
3. **Результат:** Пользователь получает теоретическую базу, достаточную для осознанной настройки модели на следующем этапе.
<br><br>

**БП-2.2: Просмотр теоретических материалов по метрикам**

**Роли:** Пользователь (Гость или Авторизованный пользователь), Система

1. **Триггер:**
Пользователь открывает информационный раздел платформы или переходит в теорию метрик (классификации или регрессии).
2. **Шаги:**
   - Пользователь выбирает интересующие метрики для задачи классификации или регрессии.
   - Система отображает описание метрик, математическую основу, и то что они отображают.
3. **Результат:** Пользователь получает теоретическую базу, достаточную для оценки полученной модели.

### 2.3. Процесс «Проведение эксперимента по предиктивному анализу»
**Цель:** дать пользователю возможность применить изученный метод к собственным данным без необходимости написания кода.

**БП-3.1: Загрузка набора данных**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь переходит на страницу обучения выбранной модели и загружает файл.
2. **Шаги:**
   - Пользователь перетаскивает CSV-файл в область загрузки или выбирает его через диалоговое окно.
   - Система проверяет расширение файла и считывает названия столбцов.
3. **Результат:** Столбцы набора данных доступны пользователю для дальнейшего выбора признаков и целевой переменной.
<br><br>

**БП-3.2: Настройка признаков, целевой переменной и гиперпараметров**

**Роли:** Пользователь, Система

1. **Триггер:**
Набор данных успешно загружен, пользователь переходит к настройке модели.
2. **Шаги:**
   - Пользователь отмечает признаки (features), на основе которых строится прогноз.
   - Пользователь указывает целевую переменную (target), переменная, которую модель должна научиться предсказывать.
   - Пользователь настраивает гиперпараметры выбранного алгоритма (например, количество деревьев, силу регуляризации, выбор метрики расстояния).
   - Система проверяет корректность выбора (например, что целевая переменная не входит в список признаков).
3. **Результат:** Параметры эксперимента заданы и готовы к запуску обучения.
<br><br>

**БП-3.3: Обучение модели и получение результата**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь нажимает кнопку «Обучить модель».
2. **Шаги:**
   - Система передаёт данные и параметры на сервер.
   - Сервер обучает модель на загруженных данных.
   - Система рассчитывает метрики качества и формирует данные для визуализации.
   - Система отображает пользователю метрики и графики (например, матрицу ошибок, важность признаков, график остатков).
3. **Результат:** Пользователь видит результат эксперимента и может оценить качество модели.
<br><br>

**БП-3.4: Повторение эксперимента с изменёнными параметрами**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь, просмотрев результат, хочет попробовать другие признаки, алгоритм или гиперпараметры.
2. **Шаги:**
   - Пользователь возвращается к настройке признаков, целевой переменной или гиперпараметров.
   - Пользователь повторно запускает обучение модели.
3. **Результат:** Пользователь получает новый результат и может сравнить его с предыдущим.
<br><br>

**БП-3.5: экспорт обученной модели**

**Роли:** Пользователь, Система

1. **Триггер:**
Пользователь, обучив модель, хочет скачать полученную модель.
2. **Шаги:**
   - Пользователь нажимать кнопку для экспорта модели.
   - Система возвращает файл с обученной моделью.
3. **Результат:** Пользователь получает файл с обученной моделью.

### 2.4. Процесс «Работа с историей экспериментов»
**Цель:** дать авторизованному пользователю возможность не терять результаты проведённых экспериментов и возвращаться к ним позже.

**БП-4.1: Сохранение результатов эксперимента**

**Роли:** Авторизованный пользователь, Система

1. **Триггер:**
Авторизованный пользователь завершает эксперимент (получает результат обучения модели).
2. **Шаги:**
   - Система формирует запись об эксперименте: алгоритм, выбранные признаки, гиперпараметры, метрики.
   - Система сохраняет запись в базе данных, привязывая её к учётной записи пользователя.
3. **Результат:** Эксперимент сохранён и доступен пользователю в истории личного кабинета.
<br><br>

**БП-4.2: Просмотр истории экспериментов**

**Роли:** Авторизованный пользователь, Система

1. **Триггер:**
Пользователь открывает раздел «История экспериментов» в личном кабинете.
2. **Шаги:**
   - Система запрашивает из базы данных список экспериментов, принадлежащих пользователю.
   - Система отображает список с краткой информацией (дата, алгоритм, ключевая метрика).
   - Пользователь открывает интересующий эксперимент и видит его полные параметры и результаты.
3. **Результат:** Пользователь может сравнивать прошлые эксперименты между собой и не терять результаты своей работы.

### 2.5. Процесс «Управление профилем»
**Цель:** дать пользователю возможность поддерживать актуальность данных своей учётной записи.

**БП-5.1: Просмотр и редактирование данных профиля**

**Роли:** Авторизованный пользователь, Система

1. **Триггер:**
Пользователь открывает раздел «Профиль» в личном кабинете.
2. **Шаги:**
   - Система отображает текущие данные пользователя (имя, e-mail).
   - Пользователь изменяет нужные поля и сохраняет изменения.
   - Система проверяет корректность данных и обновляет запись в базе данных.
3. **Результат:** Данные профиля пользователя обновлены.
