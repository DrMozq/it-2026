# Сценарии

Подробные сценарии ключевых вариантов использования из документа [Варианты использования](Варианты%20использования.md).

---

## UC-01. Войти в систему

- **Актёр:** Пользователь
- **Предусловие:** у пользователя есть учётная запись в университетском домене.
- **Постусловие:** пользователь авторизован, открыт главный экран для его роли.

**Основной сценарий**
1. Пользователь открывает приложение.
2. Система показывает форму входа.
3. Пользователь вводит e-mail и пароль.
4. Система проверяет данные и определяет роль.
5. Система открывает главный экран: для Студента и Преподавателя — поиск аудиторий, для Диспетчера — очередь заявок.

**Альтернативные сценарии**
- 4а. Неверный e-mail или пароль → система показывает ошибку, не уточняя, что именно неверно; возврат к шагу 3.
- 4б. E-mail не из домена университета → система сообщает, что вход доступен только для университетских адресов.
- 4в. Учётная запись деактивирована → система сообщает об этом и предлагает обратиться в учебный отдел.

## UC-03. Найти свободную аудиторию

- **Актёр:** Пользователь
- **Предусловие:** пользователь авторизован.
- **Постусловие:** показан список аудиторий, свободных в указанный слот.

**Основной сценарий**
1. Пользователь открывает поиск.
2. Пользователь указывает дату, время начала и окончания.
3. Пользователь при необходимости задаёт фильтры: корпус, минимальная вместимость, оборудование.
4. Система отбирает аудитории, которые доступны для бронирования, удовлетворяют фильтрам и не имеют в этот слот занятий и подтверждённых бронирований.
5. Система показывает список: номер, корпус, вместимость, оборудование.

**Альтернативные сценарии**
- 2а. Время окончания раньше начала или дата в прошлом → система подсвечивает поле с ошибкой.
- 2б. Слот вне часов работы корпуса → система предупреждает и не показывает аудитории этого корпуса.
- 5а. Свободных аудиторий нет → система сообщает об этом и предлагает ослабить фильтры или сдвинуть время.

## UC-04. Забронировать аудиторию

- **Актёр:** Студент или Преподаватель
- **Предусловие:** пользователь авторизован; выбрана аудитория и слот (через UC-03 или календарь UC-02).
- **Постусловие:** создано бронирование в статусе «Подтверждено» (преподаватель) или «На рассмотрении» (студент).

**Основной сценарий**
1. Пользователь нажимает «Забронировать» у выбранной аудитории.
2. Система показывает форму: аудитория, дата и время (заполнены), цель, число участников, комментарий.
3. Пользователь выбирает цель, вводит число участников, при желании — комментарий.
4. Пользователь подтверждает.
5. Система проверяет: число участников ≤ вместимости; слот всё ещё свободен.
6. Система создаёт бронирование:
   - автор — Преподаватель → статус «Подтверждено»;
   - автор — Студент → статус «На рассмотрении».
7. Система записывает изменение статуса в историю.
8. Система показывает сообщение об успехе и карточку бронирования.

**Альтернативные сценарии**
- 5а. Число участников больше вместимости → ошибка у поля, возврат к шагу 3.
- 5б. Слот занят другим пользователем, пока заполнялась форма → система сообщает о конфликте и предлагает вернуться к поиску (UC-03).
- 6а. Студент: система дополнительно сообщает, что заявка передана диспетчеру и решение придёт уведомлением.

## UC-06. Отменить бронирование

- **Актёр:** Пользователь (автор) или Диспетчер
- **Предусловие:** бронирование в статусе «На рассмотрении» или «Подтверждено», время начала не наступило.
- **Постусловие:** статус «Отменено», слот свободен.

**Основной сценарий (автор)**
1. Пользователь открывает своё бронирование в личном кабинете.
2. Нажимает «Отменить».
3. Система просит подтвердить действие.
4. Пользователь подтверждает.
5. Система меняет статус на «Отменено», записывает историю, освобождает слот.

**Альтернативный сценарий (диспетчер)**
- 2а. Диспетчер открывает любое бронирование и нажимает «Отменить».
- 3а. Система требует указать причину.
- 5а. Дополнительно система отправляет автору уведомление с причиной (UC-12).

**Исключения**
- Время начала уже наступило → кнопка «Отменить» недоступна.

## UC-08. Рассмотреть заявку

- **Актёр:** Диспетчер
- **Предусловие:** есть заявки в статусе «На рассмотрении».
- **Постусловие:** заявка подтверждена или отклонена, автор уведомлён.

**Основной сценарий**
1. Диспетчер открывает очередь заявок.
2. Система показывает заявки, отсортированные по дате подачи: автор, аудитория, время, цель, число участников.
3. Диспетчер открывает заявку.
4. Диспетчер нажимает «Подтвердить».
5. Система проверяет, что слот всё ещё свободен.
6. Система меняет статус на «Подтверждено», записывает историю.
7. Система отправляет автору уведомление (UC-12).

**Альтернативные сценарии**
- 4а. Диспетчер нажимает «Отклонить» → система требует причину → статус «Отклонено» → уведомление автору.
- 5а. Слот уже занят (например, другой заявкой на этот же слот, подтверждённой раньше) → система сообщает о конфликте, подтверждение невозможно; диспетчер отклоняет заявку с причиной.

## UC-10. Импортировать расписание

- **Актёр:** Диспетчер
- **Предусловие:** в системе заведены корпуса и аудитории.
- **Постусловие:** занятия сохранены; при наличии конфликтов сформирован их список.

**Основной сценарий**
1. Диспетчер открывает раздел «Расписание» и нажимает «Импорт».
2. Диспетчер выбирает файл (CSV или Excel) и указывает период действия (даты семестра).
3. Система разбирает файл и проверяет каждую строку: аудитория существует, время корректно, день недели указан.
4. Система показывает итог: число корректных строк и список ошибок.
5. Диспетчер подтверждает загрузку корректных строк.
6. Система сохраняет занятия.
7. Система ищет подтверждённые и рассматриваемые бронирования, пересекающиеся с занятиями.
8. Конфликтов нет → система сообщает об успешном импорте.

**Альтернативные сценарии**
- 3а. Файл неверного формата → система сообщает об ошибке, импорт не выполняется.
- 5а. Диспетчер отменяет загрузку, чтобы исправить файл → данные не сохраняются.
- 8а. Конфликты найдены → система показывает их список и переходит к UC-11 «Разрешить конфликт».

## UC-13. Обработать бронирования по времени

- **Актёр:** Система (таймер)
- **Предусловие:** запуск по расписанию (например, раз в несколько минут).
- **Постусловие:** статусы приведены в соответствие с текущим временем.

**Основной сценарий**
1. Таймер запускает обработку.
2. Система находит бронирования «На рассмотрении», время начала которых наступило, и переводит их в «Отклонено» с причиной «Не рассмотрена вовремя»; авторам отправляются уведомления.
3. Система находит бронирования «Подтверждено», время окончания которых прошло, и переводит их в «Завершено».
4. Система записывает изменения в историю.
