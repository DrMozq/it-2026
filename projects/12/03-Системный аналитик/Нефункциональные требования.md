# Нефункциональные требования

Каждое требование имеет идентификатор и способ проверки.

## 1. Производительность

| ID | Требование | Как проверить |
|---|---|---|
| NFR-01 | Поиск свободных аудиторий возвращает результат не дольше 2 секунд при фонде до 500 аудиторий и 10 000 бронирований. | Нагрузочный тест на тестовых данных. |
| NFR-02 | Открытие календаря занятости на неделю — не дольше 2 секунд. | Замер в браузере (DevTools). |
| NFR-03 | Система обслуживает не менее 100 одновременно работающих пользователей без деградации времени ответа сверх NFR-01. | Нагрузочный тест. |

## 2. Надёжность и целостность данных

| ID | Требование | Как проверить |
|---|---|---|
| NFR-04 | Не допускаются два подтверждённых бронирования одной аудитории на пересекающееся время, в том числе при одновременной отправке запросов. Проверка конфликта выполняется на сервере в транзакции. | Тест с параллельными запросами на один слот. |
| NFR-05 | Резервная копия базы данных создаётся ежедневно; хранятся копии за последние 7 дней. | Проверка наличия копий и пробное восстановление. |
| NFR-06 | Все изменения статусов бронирований сохраняются в истории и не удаляются. | Проверка таблицы истории после сценариев UC-04…UC-08. |

## 3. Безопасность

| ID | Требование | Как проверить |
|---|---|---|
| NFR-07 | Вход только для e-mail в домене университета. | Попытка входа с посторонним адресом. |
| NFR-08 | Пароли хранятся только в виде хеша (bcrypt или аналог). | Просмотр БД. |
| NFR-09 | Обмен данными между клиентом и сервером — только по HTTPS. | Проверка конфигурации сервера. |
| NFR-10 | Права проверяются на сервере для каждого запроса: студент не может подтвердить заявку, пользователь не может отменить чужое бронирование. | Тест запросов к API от имени разных ролей. |
| NFR-11 | Сессия завершается после 30 минут бездействия. | Ручная проверка. |

## 4. Удобство использования

| ID | Требование | Как проверить |
|---|---|---|
| NFR-12 | Бронирование аудитории из результатов поиска выполняется не более чем за 3 шага (выбор → форма → подтверждение). | Прохождение сценария UC-04. |
| NFR-13 | Интерфейс полностью на русском языке. | Просмотр всех экранов. |
| NFR-14 | Интерфейс адаптивный: корректно работает на экранах шириной от 360 px (телефон) до 1920 px. | Проверка в режиме эмуляции устройств. |
| NFR-15 | Ошибки ввода показываются рядом с полем с понятным текстом, без технических сообщений. | Ввод некорректных данных во все формы. |

## 5. Совместимость

| ID | Требование | Как проверить |
|---|---|---|
| NFR-16 | Поддерживаются актуальные версии браузеров Chrome, Firefox, Edge, Safari. | Ручная проверка основных сценариев. |
| NFR-17 | Импорт расписания поддерживает форматы CSV (UTF-8) и XLSX. | Импорт тестовых файлов обоих форматов. |

## 6. Сопровождаемость и архитектурные ограничения

| ID | Требование | Как проверить |
|---|---|---|
| NFR-18 | Архитектура клиент-сервер: веб-клиент (SPA или серверный рендеринг) и сервер с REST API. | Ревью архитектуры. |
| NFR-19 | Данные хранятся в реляционной СУБД (PostgreSQL). | Ревью архитектуры. |
| NFR-20 | Исходный код хранится в git-репозитории команды; запуск проекта описан в README. | Развёртывание по README на чистой машине. |
| NFR-21 | Время в системе хранится в едином часовом поясе университета; отображается в нём же. | Проверка бронирования на границе суток. |

## 7. Доступность (эксплуатационная)

| ID | Требование | Как проверить |
|---|---|---|
| NFR-22 | Система доступна в рабочие часы университета (пн–сб, 7:00–22:00); плановые работы — вне этого времени. | Мониторинг доступности. |
